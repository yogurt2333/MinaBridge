# MinaBridge v0.1：小程序到 Vue 2 H5 的迁移 CLI

状态：测试边界已于 2026-09-13 经用户确认，进入 GitHub 规格发布阶段；实现尚未开始。

目标仓库：https://github.com/yogurt2333/MinaBridge

## Problem Statement

已有原生微信小程序需要迁移到 Vue 2 H5。开发者需要处理模板、样式、状态更新、页面生命周期、路由及平台 API 差异，并判断生成结果是否保留了原业务行为。仅生成代码或通过构建不足以证明迁移成功。

MinaBridge 是独立开发的作品集项目。当前已有一个可运行的微信官方咖啡点单样本及操作证据，尚无迁移 CLI。第一版要围绕这份样本建立可重复的转换、验证与有限修复流程，记录真实效果；不声称已完成商业迁移或通用小程序兼容。

## Solution

提供本地 CLI，接收原生小程序工程目录和输出目录，生成独立可构建、可运行的 Vue 2 H5 工程，并给出结构化及人类可读的迁移报告。

按此前讨论采用规则转换与模型辅助改写结合的方案。明确的语法映射交给确定性转换，需要上下文的语义适配交给模型；构建和行为验证结果可驱动有轮数上限的修复。

首版验证咖啡样本的首页、规格页、结算页。交付分阶段推进，但 v0.1 完整验收包括跨页点单和有限修复，不止于静态模板生成。

下文中“已确认”来自本次讨论或原端实测；“建议默认”是本规格提出的实现选择，不冒充此前已确认决策。

## User Stories

1. As a 前端开发者, I want 从终端传入原生小程序工程目录, so that 可以在本地启动迁移。
2. As a 前端开发者, I want 指定独立输出目录, so that 原始代码不会被覆盖。
3. As a 前端开发者, I want 查看帮助和参数错误, so that 不必阅读源码才能使用工具。
4. As a 前端开发者, I want 工具识别注册页面和本地依赖, so that 生成结果包含运行所需的代码与数据。
5. As a 前端开发者, I want 获得 Vue 2 页面及启动说明, so that 可在浏览器直接检查结果。
6. As a 前端开发者, I want 基础标签、条件和循环正确转换, so that 菜单与规格选项显示完整。
7. As a 前端开发者, I want 事件参数与状态更新保留语义, so that 分类、规格选择会更新正确内容。
8. As a 前端开发者, I want 页面跳转参数与返回行为可用, so that 点单流程能跨页面完成。
9. As a 前端开发者, I want 本地商品和订单存储适配到浏览器, so that 不依赖微信运行时也能演示业务。
10. As a 前端开发者, I want 保留基础布局与样式, so that 迁移结果仍可辨认并可操作。
11. As a 前端开发者, I want 未支持的能力有明确诊断, so that 不把缺失实现误认为成功。
12. As a 前端开发者, I want 单独配置模型服务和凭据, so that 可以使用自己选择的服务。
13. As a 前端开发者, I want 模型只接收任务需要的源文件, so that 私有配置不会混入请求。
14. As a 前端开发者, I want 构建失败时看到失败阶段与错误, so that 能判断问题发生在哪里。
15. As a 前端开发者, I want 对生成工程执行真实浏览器交互, so that 验证的不只是语法。
16. As a 前端开发者, I want 单杯 22 元、两杯 44 元的业务断言通过, so that 确认核心计价和订单语义被保留。
17. As a 前端开发者, I want 保存生成页面截图, so that 能与原端基线对照。
18. As a 前端开发者, I want 失败信息反馈给模型并重新验证, so that 常见生成错误可以自动修复。
19. As a 前端开发者, I want 限制修复轮数并保留失败产物, so that 任务不会无限消耗且可以排查。
20. As a 项目作者, I want 记录各阶段耗时、模型调用次数及可获得的 token 用量, so that 后续能用数据评价方案。
21. As a 项目作者, I want 比较首次生成与修复后的结果, so that 区分模型生成效果与验证循环的贡献。
22. As a 维护者, I want 使用固定模型响应测试 CLI, so that 日常回归不依赖付费 API 或模型随机性。
23. As a 使用者, I want 在尚未执行验证时看到“未验证”, so that 不把代码生成完成误解为迁移已通过。
24. As a 项目作者, I want 保留样本来源和原有问题记录, so that 交付证据和个人贡献可以核查。

## Implementation Decisions

### 已确认范围

- 产品形态为本地 CLI，名称 MinaBridge，命令名称 mina-bridge；首个目标仅为 Vue 2 H5。
- 首个输入为微信官方咖啡点单样本的三个原生页面；原端已实测，业务代码尚未为迁移修改。
- 迁移工具应读取输入工程，而非内置针对咖啡名称、价格或页面的硬编码输出。咖啡专属断言属于验收用例。
- 输出应为普通 Vue 2 工程，不依赖微信开发者工具、Taro 或 uni-app 运行。允许输出少量明确的 Web 适配代码，不实现完整微信运行时。
- 规则转换、模型辅助、验证反馈、有限修复是此前讨论的方案方向；具体 parser、模型厂商、SDK、构建器和依赖版本尚未选定。

### 建议默认：命令与运行结果

- migrate 命令接受输入目录，out 参数指定输出目录。首版默认迁移该工程注册的页面，不增加页面选择和增量迁移选项。
- 支持 help、version，以及显式开启验证的 verify 选项。生成阶段与验证阶段分别报告状态；未开启验证不能返回“验证通过”。
- 输出目录非空时拒绝执行，输入与输出目录不得相同或嵌套。失败产物保留供检查，重新运行使用新的空目录；首版不提供强制覆盖。
- 建议退出码：0 为请求阶段完成；1 为转换、构建或断言失败；2 为参数或配置错误；3 为模型服务或执行环境故障。报告提供具体阶段与原因。
- 面向 Windows 首先验证，支持含空格和中文的绝对路径。运行依赖和版本在实现时固定，并写明启动方式。

### 建议默认：转换及平台适配

- 逻辑上区分工程读取、语法转换、模型改写、工程生成、验证与报告；围绕一次迁移任务编排，不预设多代理平台。
- 支持样本所需的基础容器、文本、图片、输入、滚动容器，插值、条件、循环别名、事件绑定及 dataset；保留数据类型和事件值语义。
- 支持样本所需的 Page 数据与方法、首次进入参数、本地 CommonJS 数据模块、setData 更新、页面导航与返回。页面返回时的实例保留和初始化不能简单等同于重新挂载。
- 将样本中的本地存储、提示、布局尺寸及路由能力明确适配到 Web。rpx 和安全区域制定可解释的适配规则；不要求浏览器复现 Skyline 引擎或微信系统胶囊。
- 未支持的自定义组件、WXS、外部服务和动态依赖应定位并报告；阻断核心流程的未知能力导致失败，范围外能力单独列为限制。
- 地址与支付为范围外能力，目标端应显示未接入，禁止复用原样本“支付失败也标记成功”的演示分支声称支付可用。
- 不主动修复原端业务问题。已知的活动订单件数提示刷新异常作为基线偏差单列；若目标行为不同，要记录差异，不能隐藏在迁移成功结论中。

### 建议默认：模型与修复

- 模型调用通过单一可替换接口，区分实际服务与测试替身；首版只需接通一个实际服务。服务商、模型名称和凭据由运行配置提供，尚未确认的服务不写死。
- 模型配置仅从显式配置及环境变量获取；密钥不写入源码、产物和报告。只读取转换所需文件，不执行输入工程中的脚本来分析代码。
- 验证执行工具控制的构建与浏览器测试。模型只产生输出工程内的文件变更，禁止修改源工程、验收断言和基线来消除失败。
- 建议默认最多 2 轮修复，可配置为 0；模型请求和构建各有超时。将失败分为可修复代码问题与凭据、网络、工具缺失等环境故障，后者直接说明并停止。
- 每轮保留错误、变更摘要、构建及行为验证结果。正常测试使用替身；至少一次实际模型迁移作为发布前证据，并记录模型标识与运行配置。

### 建议默认：报告

- 报告包含输入版本或摘要、工具和目标版本、配置摘要、页面转换状态、诊断、阶段耗时、验证结果、修复次数、调用次数和截图位置。
- 模型用量仅在服务返回时记录；不可获得时标记未知。未配置价格时不编造费用。
- 将生成成功、构建成功、行为通过、视觉待评审分别展示。发布前应比较首次生成与最终修复结果；一个样本不推算通用成功率。

## Testing Decisions

测试边界已由用户确认：以 CLI 的外部行为为主要边界，执行真实命令、检查生成工程、构建并启动后通过浏览器点击验证。只在模型服务边界设置替身，不为每个内部函数建立镜像测试。

### 已有依据

当前只有原端人工配合官方 CLI 进行的交互记录、截图和数据，没有自动化测试框架。已有样本来源为上游提交 0fe5c7df8e90582dd0b89e283df7fe32e04413f9。每个场景在隔离的浏览器存储中开始，原端新取证同样使用隔离的测试状态，避免既有订单干扰。

### CLI 契约验证

- 输入无效、文件缺失、输出目录冲突时，退出码与诊断明确且不改动原文件。
- 从最小原生样本生成工程并构建；除咖啡样本外至少一个小型合成样本用于排除针对固定内容硬编码。
- 缺凭据、超时、模型输出无效、路径越界、达到修复上限都有明确结果；不要求实际联网复现这些错误。
- 固定模型替身先返回会导致构建或行为失败的输出，再返回修复结果，验证反馈确实进入下一轮，并且最终结果取自真实重跑而非模型自述。

### 咖啡业务验收

1. 生成工程可独立安装依赖、构建和启动。
2. 首页显示 35 款饮品；点击奶茶分类后展示对应商品，进入抹茶脑袋规格页。
3. 基础价 17 元，选择大杯加 3 元、珍珠加 2 元，界面金额为 22 元。
4. 真实点击加入订单后，结算显示 1 件、22 元及相同规格。
5. 返回后再次加入，仍为同一订单，2 件、44 元；断言订单内容，不依赖每次变化的订单 ID 文本。
6. 获取规格页与结算页截图，确保内容可见、关键按钮可操作。以用户事件验证，不用直接修改页面状态或调用业务方法替代点击。

行为和金额为自动验收门槛；视觉使用固定视口、明确裁剪范围的截图人工评审，记录系统 UI、空图片和渲染差异。当前不设 SSIM 自动阈值，也不将微信节点树与浏览器 DOM 强行逐节点比较。

搜索、完整重启持久化和其他组合尚无原端实测基线，不纳入首版强制验收；不把未验证项标记为通过。后续扩展前先补原端证据。

## Out of Scope

- 网页管理界面、上传服务、账户系统、托管和多人协作平台。
- React、Vue 3、Taro、uni-app 目标与任意小程序兼容承诺。
- 完整自定义组件库、WXS、插件、小游戏、云开发迁移及真实后端迁移。
- 真实登录、地址授权、支付、扫码桌号、打印机、商户管理和线上部署。
- 自动修复原始业务缺陷、直接修改源工程或覆盖用户已有工程。
- 并发代理调度、批量仓库、增量迁移、断点恢复、npm 公开发布。
- 像素级一致性承诺、自动视觉阈值和大规模迁移指标。

## Further Notes

这是新项目开发规格，不是实现结果。CLI、模型服务接入、构建脚手架及自动回归均尚未实现。原端已验证的最小链路足够用于首轮验收，不代表样本所有功能正常。

仓库地址和用户提供链接已确认；计划使用 GitHub Issues 发布规格，并应用 to-spec 指定的 ready-for-agent 标签。后续通过 to-tickets 拆分纵向任务及其依赖，本规格不替代任务拆分。

依赖版本、parser、构建器、模型服务和具体超时时间在实现前根据兼容性与可用配置选定。遇到影响验收范围的变化需更新规格；具体文件布局与内部函数设计不在本规格中固定。
