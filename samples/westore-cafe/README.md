# 咖啡点单原端验证样本

来源：https://github.com/wechat-miniprogram/miniprogram-demo

固定提交：`0fe5c7df8e90582dd0b89e283df7fe32e04413f9`

原目录：`miniprogram/packageWeStoreCoffee`。保留 MIT LICENSE。

此目录抽取了上游三个页面和本地目录数据，业务文件原样复制；新增最小 App、页面注册和开发者工具项目配置。不是整个官方示例项目。2026-09-13 已通过官方 CLI 在开发者工具中验证分类、规格、加入订单及结算金额，详见 `../../artifacts/baseline/report.md`。

## 导入

微信开发者工具 → 导入 → 选择本目录。项目配置使用游客 AppID；如工具或 Skyline 要求真实 AppID，请在工具内使用自己的测试项目身份。无需部署后端，也没有 npm 依赖需要构建。

## 待验证

- [x] 首页编译并显示饮品、分类、价格。
- [x] 切换到奶茶分类，点击进入抹茶脑袋。
- [x] 选择大杯和珍珠，17 + 3 + 2 = 22 元。
- [x] 进入结算，商品、规格、数量、总价正确；再次加入同订单为 2 件、44 元。
- [ ] 重新进入后检查本地订单数据。

当前没有直接加减数量控件，通过再次加入订单追加商品。返回规格页时发现活动订单件数提示未刷新，详见基线报告。

## 已知边界

- 菜品由 `data/seed.js` 生成，目录和订单使用微信本地存储。
- 商品图片 URL 为空，不能把图片缺失算作迁移错误。
- 规格和结算页使用 Skyline，需要实测开发者工具基础库支持情况。
- 地址使用 `wx.chooseAddress`；首轮可止于结算展示，地址授权单独验证。
- 支付使用演示占位参数，失败时也标记模拟成功。不能作为真实支付正确性的证据，首轮不执行支付。
- 上游 Agent handoff 为可选入口；本样本测试普通页面点击路径。

迁移目标：Vue 2 H5。当前阶段只建立原端运行基线。
